最初にプロジェクトに小さな機能を追加しました。より大きな変更には、さらにしっかりとしたプロセスが必要です。GitHub Copilot CLI は既存の組織的な開発フローに沿って作業できるため、正しい方法で必要な機能を実装できます。このレッスンから数回にわたり、一般的なエージェント駆動の開発プロセスに取り組みます。Issue に基づいて機能を作成し、コードの妥当性と機能の動作を確認して、最後にプロジェクトへマージします。

> [!NOTE]
> 機能の作業を続ける間、同じ会話とブランチを使います。実際には、ファイルの種類ごとに異なるブランチや PR を作成することが一般的ですが、ここでは主な概念に集中できるよう簡略化します。

このレッスンでは、次の操作を行います。

- GitHub Issue から Copilot との会話を開始します。
- Plan モードで要件を定義します。
- Autopilot モードで新しい機能を実装します。
- コードをレビューします。
- 転送したブラウザーで機能を手動検証します。

この機能の開発は後のレッスンでも続けます。リポジトリの命令を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して QA エージェントを作成し、機能 PR を作成します。

## シナリオ

Tailspin Toys のカタログが増えており、利用者はカテゴリとパブリッシャーでゲームを絞り込む必要があります。バックログの Issue には機能の概要が記載されていますが、カテゴリを組み合わせる方法など、実装前に合意すべき詳細があります。Plan モードで決定し、Autopilot に範囲を定めた実装を任せます。

## 背景

AI コーディングエージェントを開発フローに導入しても、基本は変わりません。むしろ、さらに重要になります。一般的な開発者のフローは次のようになります。

1. 必要な作業を説明する Issue を確認します。
2. 実装するものを計画します。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新しい機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューが完了し、継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 具体的な手順はチームや組織によって異なりますが、ほとんどは上記の流れをもとにしています。

この標準的な方法を守ることで、AI が生成したコードが要件を満たし、手作業で作成したコードと同様に検証されます。

## 会話モード

**会話モード**は、エージェントにどの程度の自律性を与えるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すとモードを切り替えられます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、次に進む前に入力を待ちます。
- **Plan**: エージェントが最初に計画を作成します。プロジェクトファイルの編集は禁止されます。
- **Autopilot**: エージェントが自律的にコードを作成し、テストを実行して、タスクが完了するまで反復します。

最初に Plan モードで計画を確認し、その後 Autopilot で実装します。

## Issue から始める

絞り込み機能の作業を始める前に、Codespace に戻り、リポジトリとターミナルを準備します。

1. Codespace に戻ります。停止している場合は、再起動します。
2. 星評価の PR がマージされていることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、絞り込み機能のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を2回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての Issue を表示します。
8. 矢印キーを使って **Allow users to filter games by category and publisher** というタイトルの Issue を選択します。
9. <kbd>C</kbd> を押して Issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトの先頭に `#7` (または同様の番号) が表示されます。`#` を使うと、GitHub 上の Issue やプルリクエスト (PR) をコンテキストに追加できます。

## 絞り込み機能を計画する

計画を立てることで、機能を実装したりタスクを実行したりする前に、作業方法を定義できます。複雑な作業は、少し時間をかけて計画することをお勧めします。Plan モードに切り替え、Copilot に計画を作成させましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** であることを確認します。
2. 前の手順で追加した Issue の後に、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot はプロジェクトを調べ、最適な方法を検討して計画を作成します。

3. 絞り込み機能の動作について質問された場合は、希望に沿って回答します。正解は1つではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 上下にスクロールして計画を確認します。
6. 決定と異なる部分がある場合は、計画を修正するよう Copilot に依頼します。

## Autopilot を承認する

計画を確認したら、実装に移ります。Autopilot で Copilot に作業を任せましょう。

Autopilot を使うと、タスクが完了したと判断するまで Copilot が反復して作業します。

1. **Accept plan and build on autopilot (recommended)** またはインストール済みのバージョンに表示される同様の項目を選択します。
2. プロンプトの下にあるモード表示が **Autopilot** であることを確認します。
3. Copilot が計画に沿って作業し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認するとすぐに実装が始まる場合があります。先に計画を確認してください。依存関係が不足している、またはポートが競合していると Copilot が報告した場合は、チェック完了と判断する前に環境の問題を解決します。

## 実装をレビューして検証する

コードを生成したら、ほかのコードと同様にマージする前にレビューします。コードをレビューしてサイトを起動し、正常に動作することを確認しましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示に **Plan** や **Autopilot** が表示されていないことを確認します。
2. `/diff` を入力し、絞り込みの実装とテストを確認します。
3. 変更内容を Issue と計画で決めた内容に照らし合わせます。
4. コードのレビューが終わったら <kbd>Esc</kbd> を押して差分ビューを終了します。
5. プロジェクトのチェック結果を確認し、失敗があれば修正を依頼します。

## 新しい機能を試す

コードが良さそうでも、実際に動くか確認しましょう。前と同じようにアプリを起動し、Codespaces のポート転送を通じてサイトを開きます。

1. Copilot に次のプロンプトを送信して、アプリの起動を依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces でポート `4321` が利用可能になったら **Open in Browser** を選択します。
3. 計画で決めたとおりにカテゴリ、パブリッシャー、それらの組み合わせで絞り込みを試します。
4. リセットと結果が空の場合の動作が、Issue と決定した仕様に合っていることを確認します。
5. Codespace に戻り、Copilot に起動した開発サーバーを停止するよう依頼します。

## まとめと次のステップ

複数の会話モードを使って、機能を構築してレビューしました。このレッスンでは、次のことを行いました。

- GitHub Issue から Copilot との会話を開始しました。
- Plan モードで要件を定義しました。
- Autopilot モードで機能を実装しました。
- コードをレビューしました。
- 転送したブラウザーで機能を手動検証しました。

次は、コード生成の動作と、ドキュメント化されたプラクティスに沿う方法を掘り下げるために、[カスタム命令][next-lesson]を使います。
