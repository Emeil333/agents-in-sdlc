GitHub Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を適用または取り消し、追加のプロンプトでエージェントに指示を出せます。エディターを離れる必要はありません。

この演習では、次の操作を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューし、適用します。
- セッションの途中で指示を追加し、ハイコントラストモードに加えてライトモードの切り替え機能を実装します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の要望がありました。既定のテーマが暗すぎると感じる利用者のため、ライトモードの切り替え機能も追加します。新しい会話を始めるのではなく、既存のセッションに指示を追加して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューでは、エージェントが行う各手順を確認できます。調査したファイル、実行したコマンド、提案された編集が表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - 変更を適用するには **Keep** を選択します。
   - 変更を取り消してエージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止し、**Allow** を表示します。内容を確認し、実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードを実装し終えるまで待ちます。最後に、変更内容の概要が表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたら、同じ会話でライトモードの切り替え機能も追加します。同じチャットセッションを続けることで、変更したコンポーネント、スタイルの方針、local storage を使った設定の保存方法など、これまでの作業をエージェントが引き継げます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前の作業内容を調べ、ライトモードの変更を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. たとえばトグル UI を意図しない方法でリファクタリングするなど、エージェントの方向性を変えたい場合は、チャット入力欄の横にある **Stop** ボタンで停止し、明確な追加指示を送ります。

> [!TIP]
> 進行中のセッションに追加の指示を送ると、最初からやり直すよりも効率的です。「セレクターの重複ではなく CSS 変数を使って CSS を簡潔にする」「3つ目のトグルを追加せず、既存の設定パネルにライトモードを統合する」「両方のトグルにキーボードショートカットも追加する」など、調整や拡張を依頼できます。

## 変更ファイルをレビューする

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれます。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが提示したアクセシビリティのパターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで進行中のセッションを監視して指示を追加しました。ファイルの編集を確認し、個々の変更を適用または取り消し、コンテキストを保ったまま追加のプロンプトで作業を拡張しました。

このレッスンでは、次のことを学びました。

- エージェントの作業をリアルタイムで監視する
- 個々のファイルの編集を適用または取り消す
- 追加のプロンプトを使ってセッションの途中で指示を追加する

次の[レッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが行った変更をレビューします。
